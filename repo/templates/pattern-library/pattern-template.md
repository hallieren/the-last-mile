# Pattern Extraction Sheet (Fillable Version, Template 23.1)

One page per candidate pattern. Fill it in at project close-out; after it clears the library admission review (Template 23.3), register it in the asset register.

## The Three-Step Stripping Check (the operational definition of the generalize step, check off item by item)

- [ ] **Swap the nouns**: exception claim → queue item, reviewer → handler, repair shop → outside party; no project-specific names left in the judgment sentence
- [ ] **Drop the numbers**: project outcome numbers (such as -31%) go only into "Field Provenance", never into the judgment sentence
- [ ] **Keep the structure**: read it to a colleague who never worked the project; if they can repeat back "when to use it, when not to", the stripping is done. If they cannot, it is not done.

## Pre-Admission Self-Check (against Template 23.3, if any item fails do not admit the asset)

- [ ] At least one real on-site use with the business side (a demo, an internal team rehearsal, or a sandbox run does not count), with a linkable, checkable record
- [ ] Both the applies-when and does-not-apply-when columns are filled in, and at least one does-not-apply-when condition comes from a real "it did not work when we used it" case or a serious thought experiment
- [ ] The owner knows about it and agrees, and can name the next expected reuse scenario
- [ ] AI-generation contamination check: can name which project, which weeks, who was there; someone involved can verify it; no "industry best practice"-style statements that trace back to no actual site
